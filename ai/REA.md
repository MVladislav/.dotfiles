# REA

REA ("Reverse Engineer Anything") is an MIT MCP server and CLI for reverse
engineering APKs, firmware, native binaries, .NET assemblies, Electron/JS apps,
pcaps, and related artifacts. It orchestrates analysis engines; it does not
install them.

This repository wires REA in three places:

- **MCP server** - `OPENCODE_CONFIG_MCP_REA` in `ai/setup-ai-opencode.conf`,
  merged by `setup_opencode` into `.mcp.servers.rea` in
  `~/.config/opencode/opencode.jsonc`.
- **Agent** - `rea-investigator` in the same conf. It owns authorization checks,
  workspace confinement, evidence discipline, and the reporting contract.
- **Skill** - the upstream `reverse-engineer-anything` skill, fetched from
  `morluto/rea` at the commit in `OPENCODE_CONFIG_MCP_REA_SKILL_REV` and
  installed at `~/.config/opencode/skills/reverse-engineer-anything/`.

Do not let `rea setup --client opencode` write `opencode.jsonc`. That file is
generated by this repository. Use `rea setup --dry-run` to inspect a plan, and
`--skill-client ... --skill` if you only want REA's own skill copy.

## Version pins

The REA release pins in `ai/setup-ai-opencode.conf` are the single source of
truth:

```bash
OPENCODE_CONFIG_MCP_REA_VERSION=6.9.0
OPENCODE_CONFIG_MCP_REA_SKILL_REV=d74549e495c58eb4a560279fd9f05508401ea0a0
OPENCODE_CONFIG_MCP_REA_NODE_RANGE='^22.23.4 || ^24.22.1 || >=26.12.1'
```

The same file pins the `jadx-headless-mcp` release that REA's Android provider
expects:

```bash
OPENCODE_CONFIG_MCP_REA_JADX_VERSION=0.7.1
OPENCODE_CONFIG_MCP_REA_JADX_SHA256=6e5eacf5...
```

The CLI version drives both the MCP command and `setup-ai -upc`. The revision
must be the commit for the matching `rea-agents-<version>` tag. Find it with:

```bash
git ls-remote --tags https://github.com/morluto/rea 'rea-agents-*'
```

Bump both values together. A skill from repository `main` can describe tools
that the pinned npm release does not expose.

`setup-ai -upc` checks `rea-agents` against npm, then verifies the local JADX
bridge against the pinned version and SHA-256. It does not compare JADX with
the upstream "latest" release: REA expects 0.7.1 and upstream 1.x renamed the
artifact.

## Install and configure

```bash
bash setup-ai -irea      # npm install --global --prefix ~/.local rea-agents@<pin>
bash setup-ai -soc       # write MCP, agent, and skill; prefer ~/.local/bin/rea
bash setup-ai -upc       # compare pins and verify the local JADX bridge
```

Installation and configuration stay separate, as with the other setup-ai
tools. `-irea` requires Node.js and npm. `-soc` checks the Node version before
writing the MCP entry and warns when it is missing or outside REA's supported
range: `^22.23.4 || ^24.22.1 || >=26.12.1`.

`setup-ai -irea` also installs the free, no-auth engines automatically:

- apt baseline: `adb`, `binwalk`, `wabt`, `gdb`, `sigrok-cli`, `tshark`, `procps`
- JADX bridge: `jadx-headless-mcp` 0.7.1 JAR (pinned URL + SHA-256) and
  `default-jdk-headless`; exports `REA_JADX_MCP_JAR`
- Hopper demo: optional prompt (SHA-1 and PGP-verified .deb + apt deps);
  exports `HOPPER_LAUNCHER_PATH`

Heavy or commercial engines (Ghidra, Apktool, IDA, Kuna, JEB) remain
caller-supplied.

`setup_opencode` chooses the launch command:

- `[<node>, ~/.local/bin/rea, "mcp"]` when the pinned CLI is installed and its
  `--version` matches `OPENCODE_CONFIG_MCP_REA_VERSION`.
- `["npx", "-y", "rea-agents@<pin>", "mcp"]` otherwise. A cold npx start
  downloads the package, which is why the MCP entry sets a 180 second startup
  timeout.

The local form names the Node binary explicitly. REA records the command it
would write as `<node> <rea> mcp`; a bare `<rea> mcp` registration is reported
as `config_drift` by `rea doctor` even though it starts fine. During `-soc`,
`setup_opencode` picks a Java runtime with `jdk.compiler` (preferring
`JAVA_HOME`, then the system default JDK) and writes it to
`.mcp.servers.rea.environment` so JADX works when OpenCode is launched outside
a login shell. It also writes `HOPPER_LAUNCHER_PATH` and `REA_JADX_MCP_JAR` when
they are available.

OpenCode starts REA itself. You do not run `rea setup` or `rea mcp` manually.
After changing the config, reload or restart OpenCode:

```bash
opencode reload
opencode mcp list          # expect: rea connected
```

## Readiness

```bash
rea doctor --json
rea doctor --provider ghidra --json
rea doctor --skill --json
```

The agent runs readiness once per target, not before every step. Doctor checks
files and registrations; it cannot prove that the current OpenCode session is
connected. `opencode mcp list` and the presence of `rea_*` tools are the live
signals.

On Linux, REA needs a procps-compatible `ps` on `PATH` for process ownership
checks before it launches Ghidra, JADX, firmware tools, or static
JavaScript/Electron analysis.

## Analysis engines and prerequisites

REA itself does not install analysis engines. `setup-ai -irea` installs the free
engines below; provide any remaining tool the target needs and export its
variable in the environment that starts OpenCode, for example
`~/.profile-secrets` (mode 600).

| Target                | Tool                                                            | Select with                                                                                                                                              |
| --------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native binaries       | Ghidra 12.1+ and a full JDK (JDK 21+; Ghidra 12.2 needs JDK 25) | `GHIDRA_INSTALL_DIR`, optional `JAVA_HOME`                                                                                                               |
| Native binaries       | Hopper (free demo)                                              | prompted during `setup-ai -irea` (native .deb, published SHA-1 and PGP signature verified); `HOPPER_LAUNCHER_PATH` auto-exported to `~/.profile-secrets` |
| Native binaries       | IDA Pro plus `ida-pro-mcp` (commercial)                         | `REA_IDA_MCP_CONFIG`                                                                                                                                     |
| Native binaries       | Kuna (commercial)                                               | `REA_KUNA_COMMAND`                                                                                                                                       |
| JEB projects          | JEB client serving MCP (commercial)                             | `REA_JEB_MCP_URL`                                                                                                                                        |
| Android APKs          | `jadx-headless-mcp` 0.7.1 JAR and a full JDK 17+                | installed by `setup-ai -irea`; `REA_JADX_MCP_JAR` auto-exported to `~/.profile-secrets`                                                                  |
| Android resources     | Apktool launcher                                                | caller-supplied                                                                                                                                          |
| Android devices       | adb                                                             | `PATH`                                                                                                                                                   |
| Firmware              | Binwalk or Unblob (Linux)                                       | `PATH`                                                                                                                                                   |
| PCAPs                 | TShark 4.x and `capinfos`                                       | `PATH`                                                                                                                                                   |
| WASM                  | WABT 1.0.42                                                     | `PATH`                                                                                                                                                   |
| Offline ELF / crashes | pwntools, optional GDB/pwndbg                                   | `PATH`                                                                                                                                                   |
| JavaScript / Electron | Node.js, npm, procps `ps`                                       | `PATH`                                                                                                                                                   |
| Browser analysis      | Chrome-family browser                                           | caller-supplied                                                                                                                                          |
| Logic signals         | sigrok-cli 0.7.2                                                | `PATH`                                                                                                                                                   |
| SQLite snapshots      | Node.js 24.15+ or 26+                                           | `PATH`                                                                                                                                                   |

Free baseline for native decompilation: Ghidra plus a matching full JDK.
Hopper, IDA, Kuna, and JEB are commercial. JADX is installed by `setup-ai
-irea`; plain `jadx` is not enough, REA expects the pinned headless JADX MCP
JAR.

Static formats need no engine at all: Go and Rust metadata, PE imports and
certificates, ELF notes and hardening, managed .NET metadata, APK signatures,
model artifacts, IL2CPP metadata, Godot PCKs, PyInstaller, Deno compile
binaries, and more.

## Known doctor notes

- `skill:identity` may report
  `/home/ai/.agents/skills/reverse-engineer-anything` missing. That is REA's
  shared skill path. This repository installs the skill at
  `~/.config/opencode/skills/reverse-engineer-anything` because OpenCode V2
  derives the skill ID from that path. The warning does not block the MCP
  server or the skill. If you also want REA's shared copy, run
  `rea setup --skill-client shared --skill`; it is not managed by this repo.
- `registration:opencode` reports `config_drift` when the stored command is not
  the `<node> <rea> mcp` form REA writes itself, or when config and CLI are on
  different versions. This repository writes the Node-prefixed form; rerun
  `bash setup-ai -soc` after upgrading Node if the path changes.
- A missing engine is a per-target blocker, not a broken REA install. Continue
  with the operations the available tools support and name the unavailable
  evidence separately.

## Update

```bash
bash setup-ai -upc
```

This reports the pinned version, the locally installed CLI and skill metadata,
and the latest `rea-agents` release on npm. To update:

1. Set `OPENCODE_CONFIG_MCP_REA_VERSION` and the matching
   `OPENCODE_CONFIG_MCP_REA_SKILL_REV`.
2. Run `bash setup-ai -irea -soc`.
3. Run `opencode reload`, then `rea doctor --json`.

`rea update` updates a globally installed CLI but not this repository's pin or
the OpenCode config. Prefer the setup-ai flow so the CLI, MCP command, and skill
stay aligned.
